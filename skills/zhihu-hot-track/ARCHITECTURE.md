# 架构与泛用性分层

> 这份文档回答两个问题：**这套流程由什么组成**、**哪些部分与知乎无关可以直接搬到别的平台**。
> 目标是让"平台能力"与"通用方法论"彻底分开 —— 换平台时改适配层，方法论层不动。
> 配套：**`writing_method.md`**（书写这块通用件的完整方法，唯一被单独抽出的通用件）、**`SKILL.md`**（约束/流程/口径/踩坑）。

## 一、四层结构

```
┌─────────────────────────────────────────────────────────────┐
│ L4 数据产物层(在 ROOT, 不在 skill)                           │
│   raw/<D>/ · ext_search/<D>/ · 话题库/ · 书写skill/ · Excel/HTML │
│   —— 是"学到的东西", 跨日期累积; 换平台后结构不变、内容重学      │
├─────────────────────────────────────────────────────────────┤
│ L3 交付层(可换载体)                                          │
│   fill_excel.py · gen_html.py                                │
│   —— Excel/HTML 只是载体; 换载体只改这层, 上游数据契约不动       │
├─────────────────────────────────────────────────────────────┤
│ L2 平台适配层(换平台就改这里)                                 │
│   platform_profile.py(平台档案: 唯一注入点)                    │
│   zhihu_env.py · run.py · question_fetch.py · fulltext.py     │
│   search_many.py · question_add.py                            │
│   unfollow_question.py(知乎 DOM 选择器, 人工发布后可选清尾;      │
│   原 publish_draft.py 已随自动发帖删除, 2026-09-16)            │
│   extract_cookie.py(storageState → cookies.txt;                 │
│   cookie 半路失效的自愈配方, 2026-09-21)                        │
├─────────────────────────────────────────────────────────────┤
│ L1 通用方法论层(与平台无关)                                   │
│   契约层 contract.py(模式) · 编排 run_pipeline.py              │
│   校验 check.py / verify_html.py / verify_ext.py(证据复核)      │
│   学习 loop merge_style.py + 书写方法                           │
│   累积库 topic_lib.py · 委派合并 merge_emotion.py               │
│   待发帖列 publish_queue.py(闸门/上限/渲染/回填;                 │
│   原 publish_batch.py 的台账纪律并入, 2026-09-16)               │
│   自检 doctor.py · 组成清单守卫 check_docs.py                   │
│   元数据修复 fix_chain_source.py · 读前渲染 render_answers.py    │
│   回归验证 regress_pipeline.py                                  │
│   提示词模板 prompt_style / prompt_write / prompt_emotion      │
│                / prompt_swarm / prompt_gate / prompt_gate_pre │
│                (六个均已参数化)                                 │
└─────────────────────────────────────────────────────────────┘
```

> **文档也分层(2026-09-14)**:`SKILL.md` 只留核心(触发/准备/流程/约束/拓展板块);
> 踩坑库在 `references/pitfalls.md`、脚本与参数表在 `references/scripts.md`, **按需读** ——
> 目的是让主线程的常驻上下文少背四成内容(实测依据见 §三.5)。

**依赖方向**：L1 不 import L2 的任何东西（只用 `contract` 的路径函数与数据结构）；L2 可依赖 L1；L3 只读 L4 的数据契约。
判断一个脚本属于哪层，只需问：**把它搬到另一个内容平台，需要改几行？** 改 0 行=L1，改选择器/接口=L2，改输出格式=L3。

**2026-09-14 起这条边界是机器校验的**：平台名/域名/CLI 名只允许出现在 L2 组件里，名单写在
`platform_profile.L2_COMPONENTS`；`check_docs.py` 的第五项检查会双向比对"名单 ↔ 本文档 §二 L2 表"，
并扫出 L1/L3 文件里的平台字面量（命中即 FAIL）。**约定不再靠人记**。

**主流程里阶段0 预闸门的位置(2026-09-21 起)**：分析合并完成后 → `gen_prompts --gate --stage0` 生成
**阶段0 预闸门**提示词（检索**前**只判时政；不嵌信号表 —— extension.json 还没生成，判定只看题目与回答区；
从宽原则：拿不准一律判「是」，宁多搜不误杀）→ 判定写 `raw/<D>/publish_verdicts_pre.json` →
`gen_prompts` 默认模式按预闸名单过滤（`pregated_ranks()`），**swarm 只搜过闸 rank**（省约 70-80% 检索）→
检索后 `--gate` **阶段1** 全量两关判定（`publish_verdicts.json`）照旧，对预闸结果构成双保险。

## 二、逐组件清单（27 个脚本 + 6 个提示词模板 = 33 件）

### L1 通用方法论层（换平台 0 改动）

| 组件 | 职责 | 通用机制（可迁移的那部分） |
|---|---|---|
| `contract.py` | 契约层 | **"约定只有一个定义处"**：文件名/字段/值域/结构标记集中；生成方与校验方共用同一常量，避免两侧漂移。换平台=只换常量值；**阶段0 预闸门契约(2026-09-21)**：`VERDICT_PRE_FILE` / `VERDICT_PRE_REQUIRED` / `path_verdicts_pre()` |
| `run_pipeline.py` | 编排 | **多步且顺序敏感的流程要有一条命令**，失败即停并报是哪一关（实测手敲必漏步） |
| `check.py` | 数据校验 | 结构完整性 + **值域校验**（不做语义判断，判定权留给上游） |
| `merge_extension.py` | 汇总 + 对账 | **强 schema 校验 + 跨产物对账**（`chains[].source` 反查原答）；`--lint` 只读模式专供子 agent 自查；汇总完**自动接**事实性复核 |
| `verify_html.py` | 交付物校验 | **生成方与校验方共用结构标记**；校验项=约束的外部化（约束四写成 13 条断言） |
| `verify_ext.py` | 证据复核 | **信源门槛兜底 + 多源印证 + 同源折叠 + 链接探活 + 归档核对**；结论按 `(url, content 指纹)` 缓存 |
| `merge_style.py` | 学习 loop 汇总 | **近义折叠 + 维度归类 + 跨批频次**，为"奥卡姆取舍"提供依据 |
| `topic_lib.py` | 累积知识库 | **维度区隔(不建父子树) + url 唯一键 + FTS5 trigram 中文子串 + 原子写 + 同类体检** |
| `merge_emotion.py` | 委派合并 | **片段合并 + 与既有判定逐条对账 + 只暴露分歧**（人只复核不一致项） |
| `publish_queue.py` | 待发帖列（2026-09-16 新增；自动发帖三件套已删） | **判定权外置（判定 subagent 写 verdicts，脚本只兜底复核分歧） + 增量/中庸用确定性信号做硬闸门（基线 Jaccard / 正则黑名单） + 过闸全写、按情绪强度/最高赞排序出推荐与备选（2026-09-21） + 每日硬上限只管发布数 + 人工动作回填台账（`--mark` 带真实链接并**校验归属**：qid 必须等于该 rank 的问题 id）+ 犀利度复核回填（`--sharp`，回填后自动重跑闸门汇总与渲染）** |
| `doctor.py` | 自检 | 一条命令给全前置条件（运行时/依赖/凭证/数据/版本），**FAIL 才修，WARN 记录** |
| `check_docs.py` | 文档自检 | **"组成清单"这类文档要有守卫**：只读比对磁盘组件 ↔ 分层清单 ↔ 脚本表，并扫"改了范围却漏改别处"的旧表述。**清单会腐坏且不报错，所以必须机器检查** |
| `fix_chain_source.py` | 元数据修复 | **错配可机械修复**：用附带的可核对字段（likes/url）反查正确引用并回填，修不了的列出来交人 |
| `gen_prompts.py` | 提示词生成 | 模板填充 + 工作目录约定（**目录/文件命名契约与流程一致**，避免子 agent 猜路径）；**复合任务**（情绪+书写提取合成一个 subagent）、**前置判断提示词**（`--gate`，内嵌脚本预计算信号表）、**阶段0 预闸门提示词**（`--gate --stage0`，检索前只判时政）与**按过闸结果裁剪写稿**都在这里；**拓展提示词默认模式按预闸名单过滤**（`pregated_ranks()`：pre 文件缺失=未跑预闸门 → 回退全部 rank） |
| `render_answers.py` | 读前渲染 | **把回答按批渲染成硬换行文本**：规避 read 单行上限（否则要补读尾部），并按 `--per` 打包把主 Agent 的读取步数降到 1/5 |
| `regress_pipeline.py` | 回归验证 | **"改了脚本要证明产出没变"的固化**：临时 ROOT 复制当日数据 → 重跑交付链 → 根入口/详情页/话题库**逐字节比对** + Excel **当日 sheet 逐单元格比对**（其余 sheet 跨日累积，单日临时根整簿比对必误报，2026-09-21 起明确跳过 —— 坑 81）；差异先怀疑数据本身（坑 69） |
| `prompt_style.md` | 提取模板 | **只提"怎么做"不提"做了什么"** + 改写测试 + 固定维度 + scope/freq |
| `prompt_write.md` | 书写模板 | 读书写 skill + 链证据成文；**不检索**；内置禁令与反例清单 |
| `prompt_emotion.md` | 判定模板 | 词表 + 判据 + **边界裁决** + 标定样例 + **必填 why**（让分歧可复核） |
| `prompt_swarm.md` | 拓展模板 | 两类问题判定 + 两条发散路线 + 三类查询构造式 + **增量导向**（优先采评论区/回答区没有的新东西） + 信源门槛 + 链式 schema；「发帖短评不在本步产出」；**已参数化**（`{platform}`/`{unit}`/`{source_db}`） |
| `prompt_gate.md` | 判定模板（2026-09-16 新增） | **前置判断（时政 + 增量）的判定提示词**：内嵌 `publish_queue.py --signal` 预计算信号表 + 必填 basis/`baseline`/why + **分歧复核**纪律（判定与脚本信号相反的交主 Agent）；产出 `publish_verdicts.json` |
| `prompt_gate_pre.md` | 预闸门模板（2026-09-21 新增，与 prompt_gate.md 同类归 L1） | **阶段0 预闸门（检索前只判时政）的判定提示词**：不嵌信号表（extension 未生成，判定只看题目与回答区）+ **从宽原则**（拿不准一律判「是」，宁多搜不误杀；判 false 必须说清为何不涉公权力）；产出 `publish_verdicts_pre.json`（字段见 `contract.VERDICT_PRE_REQUIRED`） |

## 三、泛用性最强的四块（优先复用）

按"能直接搬到别的场景"排序，这四块最值得单独拿走：

### 1. 学习 loop（提取 → 奥卡姆汇编 → 应用）
`prompt_style.md` + `merge_style.py` + `prompt_write.md` + `writing_method.md`(+ 产物 `书写skill/`)
**通用到任何"要模仿某平台高赞内容风格"的场景**：社区回答、商品评论、公众号、短视频口播稿。
关键在于三段分工与"改写测试"（详见 `writing_method.md`）。

### 2. 证据纪律（信源门槛 + 论证链）
`verify_ext.py` + `prompt_swarm.md` 的信源门槛段。
**通用到任何"从 UGC 提炼事实"的调研**：分级(A事实性/B待定/C不采信/D观点)、多源印证、同源折叠识别洗稿、
归档核对(链接必须真出自检索)、以及"证据必须挂到一个想法上，并标注 印证/反驳/边界"。

### 3. 委派给 subagent 的三条纪律
①**权威校验器要给子 agent 用**（`merge_extension.py --lint` 只读模式，不能让它自己写校验器，实测自写的漏判）；
②**不信自述、由脚本复核**（实测 3 个 rank 自报合规实为 5 处硬错）；
③**判定类任务必须给判据 + 标定样例 + 必填理由字段**，并对账分歧（实测无判据时一致率 20%）。

### 4. 对外动作的发布纪律（2026-09-16 改制：自动执行部分已删，制度保留）
台账=唯一事实源 + 逐条可验证（回填**真实回答链接**，"点了发布"≠"发出去了"） + 每日硬上限不递补 +
**人工终审**（机器只到"待发帖列"为止，扣扳机的永远是用户本人）。
浏览器自动发帖三件套已于 2026-09-16 整体删除——**"对外不可逆动作由人扣扳机，机器负责把『该发什么/发到哪一步』记成台账"**
（台账思想存活在 `publish_queue.json`）。
**通用到任何"对第三方平台做不可逆动作"的场景**（发帖、提交、上架）。

### 5. 成本纪律（2026-09-14 会话记账实测后加入）
**先量占比，再改结构**：把一次运行的全部会话按 `tokenUsage` 记账（主 Agent 与每个子 agent 分开），
得到"成本长在哪"的实测结构 —— 本次是 **Swarm 58% / 主 Agent 29% / 书写+情绪 12%**。
然后按四条通用手法降本，**都是可搬到别的 agent 流水线的**：
① **给 LLM 的中间产物先瘦身**（检索归档 → slim：只留判断用得上的字段，实测 20–46KB → 1/4）；
② **按需加载文档而不是常驻**（踩坑库/参数表拆到 `references/`，用时再读）；
③ **下游有硬上限就裁剪上游**（2026-09-21 修订：写稿端改为**过闸全写**、不按上限预裁剪，上限 3 条只裁决**发布数**——推荐/备选由队列排序；该手法仍适用于"上游产出远多于下游消费"的场景）；
④ **同一份输入不要读两遍**（互不依赖的读答任务合成一个 subagent）。
另有一条反向纪律：**权威校验、事实复核、结构断言这些脚本在做的事不要"省"** —— 它们不花 token，省了只换来返工。

## 四、换平台的操作顺序（迁移指南）

1. **先填档案**：在 `platform_profile.py` 里加一个平台档案（平台名/单元/交付物命名/来源文案/域名类别/接口地址/URL 模板/检索库名/CLI 与环境变量名/凭证服务名）。
   也可以用 `TRACK_*` 环境变量直接覆盖内置档案的字段（未内置平台会走"通用档案"），先把 L1/L3 跑通。
2. **写 L2 适配**：照 `run.py`/`question_fetch.py` 的形状实现"取榜单 → 取条目内容 → 补全文 → 发散检索"；
   `doctor.py` 的检查项加一条平台凭证。
3. **复用 L1 全套**：校验、证据复核、累积库、学习 loop、待发帖列直接可用；改完跑 `check_docs.py`（平台字面量守卫会告诉你还有哪里没解耦）。
4. **换 L3 载体**（如从 Excel/HTML 换成 Notion/飞书）：只改 `fill_excel.py`/`gen_html.py`，
   注意 `contract` 里的结构标记要与新校验方共用。
