# 书写方法（通用件）

> **这是与平台无关的方法论**：如何让 Agent 从"某平台高赞内容"里学会**怎么写**，并把学到的东西
> 固化成一份可复用、可累积的规范，再据此成文。
> 适用于任何"要模仿一个内容社区的表达风格"的场景（社区回答、商品评论、公众号、短视频口播稿…）。
> 本流程的具体产物是 `<ROOT>/书写skill/书写skill.md`（知乎语料学出来的 v1），但**方法本身不属于知乎**。

## 一、为什么必须拆成三段（不能一段包办）

```
高赞语料 ──① 提取──▶ 候选规律 ──② 奥卡姆汇编──▶ 书写规范 ──③ 应用──▶ 成文
         (subagent,分批)      (主 Agent)                (subagent)
```

| 若把哪两段合并 | 会出什么问题（实测） |
|---|---|
| ①+③（边写边学） | 会在规范定稿前先写一遍 → **必然返工**；而且书写时注意力在内容上，学不到可迁移的写法 |
| ①+②（提取端直接出规范） | 会把**低频个人偏好**写进规范（实测有 freq=1 的特征只出现在单一作者身上），规范被噪音污染 |
| ② 由脚本做 | 脚本能折叠近义、能算频次，但**取舍要判断力**：哪些是"约束力强的禁令"、哪些是"数据假象"，只有人能定 |

## 二、① 提取端（subagent，分批）

**铁律：只提"怎么写"，完全不涉及"写了什么"。**

判定工具是**改写测试**：把这条规律套到一个完全无关的话题上，是否仍然成立？不成立 → 你写的是内容，删掉。

- ✅「首句即判断句，结论谓语进前 30 字」（套任何话题都成立）
- ❌ 任何具体事实、数字、人名、机构名、例名、结论
- ❌ 空话（"语言生动""逻辑清晰"）→ 必须换成可操作特征（"动词短句串行，平均句长 ≤15 字，少用形容词"）

**固定维度**（值域固定，便于跨批汇总；本流程用 11 个，可按场景增删）：
开头方式 / 结构推进 / 句长与节奏 / 人称与口吻 / 情绪表达 / 论证顺序 / 结尾方式 / 标点与格式 / 词汇习惯 / **犀利度与锋芒**（2026-09-16 新增） / 避免的写法

> **犀利度是硬要求**（2026-09-16 起，用户要求发帖语言一定要犀利）：该维度**至少给 2 条 patterns**
> （"怎么把话说狠"的具体手法），且**中庸/和稀泥的写法一律进 `avoid`**——学习端就要开始筛，
> 不能等书写端再治。

**每条必须带三个字段**：
- `scope`：`普遍`（多数高赞都这样）还是 `个别`（单一作者的选择）——**这是后续取舍的主要依据**
- `freq`：出现该特征的高赞条数（**要真数，不要凭印象**；建议写一次性脚本统计标点/句长这类可量化项）
- `why`：一句话说明为什么有效（迫使你判断它是否真的成立）

**权重与对照**：
1. 按点赞加权——低赞回答的写法**不算规律**，只能作反面对照（"中低赞才出现的写法"要明确排除）。
2. 语域要先分流：同一批里常并存"冷静推演体"与"热讽体"，**只在某一种语域里出现的特征要降为「个别」**，不要当通用写法。
3. `avoid` 单独成组：高赞**明显不做**什么（这类条目的约束力往往最强）。

## 三、② 汇编端（主 Agent，奥卡姆剃刀）

先用工具把候选池整理好（本流程是 `merge_style.py`：折叠近义、按维度归类、给跨批频次），再人工取舍。

**剃刀四条（按顺序执行）**：

1. **先剔"非写作因素"**（最重要，详见第四节）。
2. **合并近义**：不同批次会用不同措辞表达同一条规律（实测 4 批各自都写了"首句即判断"）。
   判据：两条规律**互换后论点强度不变**，就是同一条 → 留措辞更具体、可操作性更强的那条，频次相加。
3. **按频次取舍**：只留**跨批复现**（≥2 批）或 `freq` 显著高的；单批 `freq=1` 的个别偏好直接删——
   它们不是规律，是某个作者的个性。**被删的不要丢**：记进维护记录的"未采纳"里，供下次比对。
4. **禁令优先于技巧**：`avoid` 类条目（"不写背景章节""不用双面论证"）对写作的约束力比正向技巧更强，
   即使频次略低也要保留。

**汇编产物的形状**（本流程 `书写skill.md` 的结构，可直接照用）：
- 开头一段"**这是什么 / 谁在用 / 怎么累积**"
- **第〇节：使用前须知** —— 放"容易学错的地方"（数据限制、语域分野），**放在最前面**，因为它决定后面怎么用
- 按维度分节的正向规则（每条：做法 + 为什么 + 证据频次）
- **避免的写法**：表格，每条附频次证据
- **一页速查**：写给实际动笔的人（首句/推进/段落/句长/人称/情绪/犀利/结尾/标点/词汇/禁止）
- **维护记录**：日期 + 版本 + 变更（含"未采纳了什么、为什么"）

**篇幅纪律**：本次 106 条候选 → **26 条规则 + 8 条禁令**。规范越长越没人照着写；
能用表格和速查表达的，不要写成长文。

## 四、必须提防的"数据假象"（踩过一次，代价很大）

> **任何"从数据里学规律"的环节，都要先问一句：这个特征是作者的行为，还是我的管道造成的？**

实测事故：4 个提取 subagent **各自独立**报告"抓取到的正文没有换行符"，于是有批次把
**「单段成文、不空行」（freq=24）** 写成了高赞普遍写法。若不拦，此后所有回答都会变成不分段的一大坨。

**同类假象清单**（提取前先过一遍）：
| 管道动作 | 会被误读为 |
|---|---|
| 统一去掉换行/空白 | "不分段""单段成文" |
| 去掉表情、图片、代码块 | "不用表情/不配图" |
| 字段截断 | "回答都很短" |
| 排序规则改变 | "高赞都这么写" |
| 只取前 N 条 | "普遍做法"（其实是采样偏差） |

**处理方式**：写进规范的**第〇节**，明确写"**不能**推出 X"——比默默删掉更有用，因为下一个用的人会再犯。

## 五、③ 应用端（subagent，不检索）

书写 subagent 的输入只有两样：**书写规范** + **已定稿的事实素材**（本流程是链证据 JSON）。
它**不做检索**——素材缺口属于上游责任，让它补搜会把"写作任务"变成"调研任务"，两边都做不好。
**2026-09-16 起只有过闸 rank 才进入本段**（前置判断三道闸门之后，每日 ≤3 条），产物是**发帖短评**。

内置到模板里的硬约束（本流程的用户定稿，可作默认）：
- **篇幅 50–100 字**（2026-09-16 起；**原为 ≤500 字的拟答参考稿**，该口径已废弃——发帖物是一条态度鲜明的短评，不是一篇完整回答）
- **骨架 = 判断 → 机制/代价 → 落点**；**第一句就把判断钉死**，不许铺垫
- **语言要犀利，允许暴论**（用户原话"语言一定要犀利"）；**中庸句式进黑名单**
  （本流程 `contract.MEDIOCRE_PATTERNS`，脚本正则硬拦——写法上主动避开"一方面…另一方面""见仁见智""理性看待"式和稀泥）
- 正文**零链接**（来源留在素材层）；事实纪律不变：数字/主体/出处照素材写，不编造

并要求它**自报落实了规范的哪几条**（便于抽查它是否真的读了规范）。

## 六、累积与版本

规范是**跨日期累积**的（与知识库同构，越用越准），不是每天重写：
- 每次运行后新增/修订条目，**并在维护记录里写清删了什么、为什么**（否则下一轮又会把噪音加回来）
- 判断"该合该删"时以**跨日期复现**为准：今天 freq=1、明天又在别的批次出现 → 升级为规律
- 原始候选必须留档（本流程在 `ext_search/<D>/style/style_batch_*.json`），
  否则无法回答"这条规则是哪来的、当初为什么没采纳另一条"
