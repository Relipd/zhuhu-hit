## 硬要求（用户三轮反馈后定稿，违反即重写）

**视角与口吻**
- **纯路人视角**：把自己当成刷到这个问题的普通观众/消费者，带着参与感说话；**不立人设**（不许「我是编剧」「我在这行十年」）。
- **允许暴论**：该拍桌子就拍，敢下狠判断、敢点名某种机制或某类做法，不要四平八稳。
- **禁止 AI 腔**：不准出现「先给结论」「总结一下」「值得注意的是」「综上所述」「首先/其次/最后」
  「客观来说」「说白了就是」这类结构提示语；也不准出现「推断：」「（推断）」这种**标签式**标注 ——
  要表达不确定就用「我猜」「说不准」「大概率」「这话没实据」。

**内容五条（缺一不可）**
1. **第一句就把判断钉死**，不要任何铺垫。
2. 讲清**为什么会这样**：机制、激励、成本被谁分给了谁 —— 不是复述现象。
3. 点出**各方诉求**，以及它们之间**不可兼得**的那一处矛盾。
4. **主张句必须自带解释**：每段第一句是该段结论，紧跟一句"为什么成立"，再一句"所以意味着什么"。不许只丢结论。
5. 保留 **2–3 个**关键事实/数字即可（撑主张，不是炫信息量）。

**讲清楚 > 精简（优先级最高）**
- 省字只许从**例子**里省，不许从**讲道理**里省；上一版写成电报体（「需求侧一样。微短剧用户 6.96 亿…时间投给快反馈了。」）是错例。
- 凡出现专有名词（人名/机构/片名/平台名），**要么一句话交代他是谁，要么直接不用他**。
- **明白的标准**：完全不了解这事的人，只读第一段和最后一段就能复述你的立场；读完中间段落能说清"为什么会这样"和"卡在哪一处矛盾"。

**篇幅与格式**
- **正文 ≤500 字**（建议用满 420–495）；**正文里不许出现任何链接**。
- 【平台注记】{platform_notes}
- markdown，首行 `# 标题`（20 字内、可以带劲），自然段推进、**不写小标题**；
  结尾一句要能被人直接转述。文件里不要写"这是一篇回答稿"之类说明文字。

**反例（命中任何一条都要重写）**
- ✗「先给结论：…」　✗「推断：当…就是理性的。」（书面、AI 腔）
- ✗「需求侧一样。A 是 X、B 是 Y。时间投给快反馈了。」（电报体：数字堆完就走，没说清所以）
- ✗「全勇先承认审美滑坡…他更准。」（读者不知道他是谁）
- ✗ 任何 `[来源](http...)` 或裸 URL　✗「一方面…另一方面…」「见仁见智」「不可一概而论」「值得深思」

## 事实纪律
- 只用 `rank_{rank}.json` 里已有的证据与锚点；**不要新增未经检索核实的事实**，也不要编数字/案号/人名。
- 链里标为「推断」的内容，在稿子里要用不确定语气说出来，不能写成既成事实。
- 证据里的 url 不要写进正文（正文零链接），但你的论证必须与那些证据一致。

## 收尾纪律
- **不要修改** `rank_{rank}.json` / `answers_summary.json` / `analysis.json` / `hot.json` / 书写 skill；
- **不要检索**（没有素材缺口也照样不要补搜；若确实发现链明显支撑不足，在回复里说明"证据偏薄"，由主 Agent 决定）；
- 不要跑 `merge_extension.py` 的写出模式；临时 .py 脚本删掉。
