## 环境（严格遵守）

- **禁止** `python -c "..."` 内联执行：PowerShell 会剥掉引号导致语法错误。需要跑代码就**写一个 .py 文件再执行**。
- 读文件用 read 工具；跑命令用 pwsh 工具。
- ROOT = `{root}`，DATE = `{date}`，你负责的 rank = **{ranks}**。
- 回答数据：`{root}\raw\{date}\answers_summary.json`（顶层数组，找 `rank` 匹配的那一项；answer 含 `url`/`text`/`likes`）。
- **渲染再读**：先写一次性 py 脚本，把你负责的每个 rank 的回答正文**按 1400 字硬换行**落盘成文本文件（放 `D:\DSH\_emo_{tag}.txt`），再用 read 读。
  必须硬换行 —— read 工具**单行上限 2000 字符**，不换行会把长回答截断，你会基于残文判断（这是踩过的坑）。

## 你的任务
逐条读回答原文，为**每一条回答**判定三个字段：

| 字段 | 值域 | 含义 |
|---|---|---|
| `emotion_tags` | 12 选 1–3 个 | 愤怒 / 讽刺 / 忧虑 / 失望 / 无奈 / 共情 / 振奋 / 认同 / 调侃 / 审慎 / 悲悯 / 漠然 |
| `emotion_intensity` | 1–5 | 1 极淡 → 5 极强 |
| `emotion_target` | 6 选 1 | 当事人 / 涉事机构 / 制度环境 / 舆论与媒体 / 自身经历 / 泛化社会 |

## 判据（必须照此执行，否则跨批次不可比）
- **标签看行文里真实存在的情绪载体，不是看立场对错**：
  - 冷静举证、法条分析、第三方转述 → `审慎`（哪怕结论是批评性的）
  - 举证里夹讥刺、反话、阴阳 → `审慎`+`讽刺`
  - 通篇反讽、骂战、指名冷嘲 → `讽刺` / `愤怒`
  - 只是玩梗、看戏、戏谑 → `调侃`
  - 温情怀念、悼念逝者 → `共情` / `悲悯` / `认同`
  - 拥抱变化、为某方叫好、亢奋 → `振奋` / `认同`
  - 冷眼旁观、无所谓、犬儒 → `漠然`
  - 讲到他人苦难而生怜悯 → `悲悯`
  - 讲不通、算不清、认命式妥协 → `无奈`
  - 对结果或主体的落空感、不信任 → `失望`
- **强度看情绪浓度**（不是立场强弱）：冷静举证 1–2；有明确情绪但不激烈 3；通篇激愤/狂欢/痛心 4–5。
- **指向看情绪冲着谁**：骂涉事企业→`涉事机构`；骂规则体制→`制度环境`；骂舆论场/媒体/网友→`舆论与媒体`；谈自己经历→`自身经历`；泛谈社会风气→`泛化社会`；指向具体当事人→`当事人`。
- 标签不许重复，1–3 个，宁少勿凑：只写真正贯穿这段文字的。
- **禁止**用任何脚本、词库、关键词统计、情感模型做判定 —— 必须是你读完原文后的判断。

## 边界裁决（2026-09-13 实测补充：首批 subagent 与主 Agent 判定仅 20% 完全一致，差异集中在下面四处，故给出硬裁决）
1. **`讽刺` vs `调侃`**：做一次测试——把标签去掉，读者会不会认为作者在骂谁？
   会（有明确攻击对象：某人/某机构/某种说法）→ `讽刺`；只是逗趣、自嘲、看戏、自己也乐在其中 → `调侃`。
   两者可叠加，但**先答上面那个问题**再决定哪个在前。
2. **强度锚点**（不要凭"梗好不好笑"定）：1 = 几乎不带情绪，纯信息罗列；2 = 情绪只在句尾带一下；
   3 = 通篇有情绪但在克制范围内；4 = 情绪是主要推动力（排比、感叹、反问密集）；
   5 = 情绪压倒论证（连用问号叹号、直接痛斥）。**玩梗类按"这个梗在全文占多大份量"定**：
   一句揶揄收尾 = 2，通篇靠玩梗推进 = 4。
3. **指向的优先序**（抽象评论最容易吵这里）：同一段既骂具体主体又泛谈社会时，**取最具体的那一个**——
   `当事人` / `涉事机构` > `制度环境` > `舆论与媒体` > `泛化社会`。只有通篇找不到具体对象时才填 `泛化社会`。
4. **负面情绪四选一**：`失望` = 期望落空（对某个结果或主体）；`无奈` = 无力改变、只能接受；
   `忧虑` = 担心未来会变坏；`悲悯` = 对他人苦难的怜惜。可以叠加，但叠加时每个都要能说出各自的触发句。

## 标定样例（照这个尺度做）
1. 一条谴责"举报人反被报复性检查"的长文，通篇讽刺+愤怒，结尾连用问号表达不平 →
   `tags=["愤怒","讽刺","无奈"], intensity=5, target="制度环境"`（情绪冲的是"系统无人识别异常"）
2. 一条逐条对照法律条文的冷静分析，指出取证障碍、给出维权路径，情绪不外露 →
   `tags=["审慎","忧虑"], intensity=3, target="制度环境"`
3. 一条悼念主持人的短文，回忆她"被投诉不会笑却当场开怀大笑"，结尾"愿一路走好" →
   `tags=["共情","悲悯"], intensity=3, target="当事人"`（情绪冲着逝者本人）

## 输出（强制 schema）
写到 `{out}`，**顶层是单个 JSON 对象**，键是 rank 字符串，值是**按回答显示顺序排列的数组**（长度必须等于该 rank 的回答条数）：

```json
{{
  "1": [
    {{"tags": ["愤怒", "讽刺", "无奈"], "intensity": 5, "target": "制度环境",
      "why": "结尾连用问号指名痛斥，且落点是系统无人识别异常"}},
    {{"tags": ["审慎", "忧虑"], "intensity": 3, "target": "制度环境",
      "why": "通篇对照法条举证，只在取证障碍处透出担忧"}}
  ]
}}
```

硬约束：`tags` 非空、≤3 个、不重复、取自词表；`intensity` 是 1–5 的整数；`target` 取自 6 类；数组顺序与 `answers_summary.json` 中该 rank 的 `answers` 顺序**逐一对应**（第 1 条对第 1 条）。
**`why` 必填**：每个标签各一句 ≤20 字的触发依据（"为什么是这个标签/这个强度/这个指向"）。主 Agent 要靠它复核分歧，写空话（如"行文带有情绪"）等于没写。
