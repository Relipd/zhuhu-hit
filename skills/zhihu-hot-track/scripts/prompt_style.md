## 铁律：只提"书写逻辑与语言习惯"，不提内容
你产出的每一条都必须是**可迁移到任何话题**的写法规律。判断标准：

- ✅ 可以写：「开头第一句直接把判断钉死，不做背景铺垫」「段间靠"成本/收益"这类机制词推进，而非时间顺序」
      「通篇用第二人称把读者拉进场景」「反讽靠引号包裹关键词实现」「结尾用一句可被单独转述的判断句收束」
- ❌ 不许写：任何具体事实、数字、人名、机构名、案例名、结论本身；也不许写"这篇文章讲了 XX"。
- ❌ 不许写空话：如「语言生动」「逻辑清晰」「有说服力」——必须给出**可操作的写法特征**
      （例：不说"语言生动"，而说"用动词短句串行，平均句长 15 字以内，少用形容词"）。
- **改写测试**：把这条规律套到一个完全无关的话题上，是否仍然成立？不成立说明你写的是内容，删掉。

## 观察方法
1. **以高赞为权重**：`likes` 高的{unit}，其写法特征优先；同一条特征在多个高赞回答里重复出现 → `freq` 记为出现的条数。
2. **要比较不要罗列**：同一维度下，哪些是**普遍做法**（多数高赞{unit}都这么写），哪些是**个别选择**（只有一个作者这么写）——`scope` 字段区分 `普遍` / `个别`。
3. **正面特征优先，但要给反例**：`avoid` 维度写"高赞明显不做的写法"，这对写作最有约束力。
4. 【平台注记】{platform_notes}

每条都要**能指导写作**：写成"做法 + 一句为什么有效"。

## 输出（强制 schema）
写到 `{out}`，**顶层是单个 JSON 对象**：

```json
{{
  "ranks": [{ranks}],
  "patterns": [
    {{"dim": "开头方式",
      "rule": "第一句直接把判断钉死，不做背景铺垫，也不写"这个问题很复杂"式的缓冲",
      "why": "读者在前 3 秒决定是否继续读，判断前置等于把结论当钩子",
      "scope": "普遍",
      "freq": 4,
      "example_form": "（只给句式骨架，例如：结论——驳回理由）"}}
  ],
  "avoid": [
    {{"rule": "不写大段行业背景/历史沿革", "why": "高赞回答几乎不从背景讲起，背景一律压缩成半句插在论证里",
      "freq": 5}}
  ],
  "notes": "你的观察过程与取舍说明（哪些特征只出现在低赞回答里所以没采纳）"
}}
```

硬约束：
- `dim` 必须取自上面 10 个维度（`avoid` 数组除外，它固定放"避免的写法"）；
- `rule` 是**可操作的写法**，不含任何具体事实/数字/专名；`why` 一句话说明为什么有效；
- `scope` ∈ `普遍` / `个别`；`freq` 是出现该特征的高赞{unit}条数（整数）；
- 至少 12 条 patterns、至少 3 条 avoid；`notes` 必填；
- **`example_form` 只写句式骨架**（如「结论——反例——机制——落点」），不许填真实句子。
